# v0.2.3 AI 重点漏标诊断与改进

日期：2026-10-31。开发基线为当日最新 `origin/main`（v0.2.3），分支为 `codex/highlight-recall-v023`。没有修改或合并 main，没有安装开发版，没有调用真实 AI API，没有重新翻译或写入真实论文 PDF。

## 为什么 38 页论文只有 2 处标注

检查对象是已有中文附件《基于多标签嵌入的短期跨类别投诉复发预测框架》（Law 等，2026），共 38 页。读取标注层确认：智能档，2 处标注，分别位于第 1、2 页。

旧标注层的文本身份、模型/服务配置身份与旧缓存全部匹配；按旧版生产规则重建缓存键，命中 36 批，缺失 0 批。只读复核得到：

| 阶段 | 旧版可恢复的结果 |
| --- | ---: |
| 提取的几何文本段/表格碎片 | 2225 |
| 符合旧版发送条件的段落 | 286 |
| 含这些段落的已缓存请求批 | 36 |
| **经过旧版校验后**的完整候选池 | 3 |
| 智能档排除 supporting | 1 |
| 最终标注 | 2 |
| AI 原始返回数、首次校验各原因拒绝数 | 旧版未保存，无法恢复 |

不能把缓存中的 3 个候选解释成“AI 只返回 3 个”。旧版在缓存前已经丢弃不符合本地规则的候选，也静默丢弃了请求外 ID；历史原始响应不在缓存中。

主要结构性原因有三项：

1. **实际章节未识别，表格文字却改变了全篇状态。** 中文译文的章节编号后存在 U+0003 控制分隔符，旧版无法识别第 7 页“3. 方法”、第 15 页“4. 结果与讨论”和第 34 页“5. 结论”。反而将第 3 页文献表中的“结论：……”识别为结论标题，将第 4 页小字号表头“方法”识别为方法标题。之后直到参考文献，正文一直沿用 methods。286 个符合发送条件的段落中有 260 个被归为 methods。
2. **章节错误与类别硬过滤叠加。** `local_evidence()` 对 methods 中的 finding、data 一律返回 False；innovation 还必须命中“本文提出”“首次”等词。即使 AI 正确选中后面的真实结果，也会被本地规则丢弃。其他章节的 data、finding 也受有限指标名或固定动词控制。这是可从代码和真实片段复现的系统性问题，但每一条历史候选具体因何被丢弃已经不可追溯。
3. **候选池本身已很小，密度选择再排除 1 个。** 缓存只留下第 1 页两个 data（core、supporting）和第 2 页一个 innovation（core）。智能档只保留 core、important，因此最终为 2。旧版已经没有每页配额；单纯加配额无法修复以上问题。

## 改进后的识别与安全边界

- 支持中文章节编号、中文序号、罗马数字、附录、自定义编号标题和同行摘要。控制字符只在标题分类与背景展示时规范化，引用原文、字符和坐标不改写。以全篇中文正文主字号辅助识别，避免密集表格页的小字号分布把表头当章节。
- 除标题、参考文献、不可映射/乱码、中文不足的碎片等工程性条件外，各章节正文均可送 AI；未知章节、引言、方法、附录无需命中特定措辞。
- 每批请求提供论文标题、摘要和章节结构。背景只用于理解，允许引用的 ID、原文仍限于当前批次。
- 删除类别对应的词表和 methods 否决规则，学术价值、作者归属和方法贡献交给 AI 结合背景判断。自报 confidence 校验为有效 0–1 数值，不再使用任意的 0.8 作为真实性门槛。
- 精简保留理解主旨必需的 core；智能加上独立重要的数据来源/划分、机制、比较与适用条件；充分加上有独立阅读价值的补充证据、消融、稳健性和失败情形。不设置篇、页、段的固定条数或比例。
- 仍要求唯一、精确、连续的文本匹配；改写数字不能定位。保留同句关键限定条件、置信区间及 ± 不确定性检查、防重叠、坐标边界、已有注释/图片/文本保护、原件别名保护与安全安装流程。允许 12–600 字符的完整引用，不再为 180 字符上限截断重要限定。
- 超长段按原始字符偏移拆包，不因超过 5000 字符整段丢弃。

新规则使用 `transyh-ai-highlights-v3-contextual-recall` 提示版本、`contextual-sections-v1` 提取版本和 `semantic-importance-density-v2` 选择版本，使用独立的 `candidate_batches_v3` 缓存表。旧 `selections` 表原样保留，但不复用。密度和并发变化仍复用新版本的完整候选池；提取、提示或选择规则变化会隔离缓存。

## 是否仍有明显漏标

已有 PDF 仍保留原先 2 处标注，因为本轮没有对真实论文发起新 AI 请求或安装新标注层；上表 7 处内容在现有标注层中仍明显缺失。可以确认它们已不再受上述本地规则阻挡，不能确认真实模型会全部选中。

仍存在工程边界：1910 个中文不足的碎片中包含大量独立表格数字/短标签；当前没有把这些碎片重建成可安全理解的整行表格。另有 41 条非水平文本行不进入精确定位。跨页/分段的连续证据不能拼接成一个引用；原文中的隐藏分隔符若被模型改写为空格，仍会因精确匹配失败而拒绝。这些范围均可能继续漏标，不能宣称“已经没有明显漏标”。新统计会区分它们与 AI 的语义选择。

## 统计与复现

`highlights()` 的返回值及进度事件新增 `diagnostics`，不含正文、请求体、API Key 或服务/模型原名：

| 字段 | 含义 |
| --- | --- |
| `extraction` | 页数、跳过的旋转页、未映射文本行数 |
| `paragraphs` | 提取/符合条件数量、逐原因排除数、逐章节数量 |
| `ai` | 本轮实际发送段落数、返回候选总数、逐原因拒绝数 |
| `cache` | 复用批数/段落数、历史返回候选数与历史拒绝原因 |
| `selection` | 进入密度选择的候选数、本轮密度/防重叠等拒绝数 |
| `finalHighlights` | 最终条数 |
| `reusedExistingLayer` | 直接复用现有同版本标注层；本轮没有生成候选 |

拒绝原因包括 schema、unknown_paragraph（含跨批 ID）、ineligible_*、category、quote_length、confidence、omitted_qualifier、unmatched_or_ambiguous、importance、density、duplicate_or_overlap。缓存只保存偏移、类别、重要性与计数，不存论文原文或模型响应。

新请求和缓存的候选损耗分开累计，重复运行不会把缓存历史候选伪装成本轮 AI 返回。非直接复用标注层时，提取数等于符合条件数加排除数；返回候选数等于首次拒绝数加进入选择数；进入选择数等于选择拒绝数加最终标注数。

只读诊断命令：

```bash
.venv/bin/python scripts/diagnose-highlights.py /absolute/path/to/paper.pdf \
  --baseline-ref origin/main --output tests/output/highlight-diagnosis.json
```

可选 `--include-text` 将原文摘录写入本地报告，应保密且不提交。`--legacy-cache /absolute/path/to/highlight-cache.sqlite3 --legacy-config-stdin` 可从标准输入提供仅含 baseURL/model 的 JSON，按旧版生产身份关联旧缓存；不需要 API Key，不产生 API 请求。诊断工具以 SQLite `mode=ro` 读取旧缓存，不实例化写缓存，不调用 PDF 保存或安装函数。

本轮本地详细结果位于被忽略的 `tests/output/highlight-recall-38-page-readonly.json`，含段落/章节计数、旧缓存核对和 7 个片段的精确位置。没有将真实 PDF、缓存数据库或含全文片段的诊断 JSON 提交到仓库。

## 验证

先运行原有 52 项重点测试作为基线，再用 Mock 与合成/现有测试 PDF 验证修改，之后才打开真实 38 页论文只读诊断。最终 `npm run test:highlights` 的 82 项相关测试通过，`npm run typecheck` 通过。测试覆盖分阶段计数守恒、跨批/非法候选计数、背景实际入请求、非关键词候选、中文编号/隐藏分隔符、小字号表头、三档密度、缓存隔离与计数复用、数字篡改、限定条件、长引用、防重叠和原 PDF 保护；诊断报告也不能通过文件别名覆盖源 PDF 或旧缓存。

没有执行完整 Zotero 回归、真实 API 或全文翻译。已目视检查真实论文第 1、15 页的只读渲染以确认标题、表头与章节版式；Mock 的渲染测试确认定位和原文保留。这些验证不证明真实模型的学术判断准确率。
